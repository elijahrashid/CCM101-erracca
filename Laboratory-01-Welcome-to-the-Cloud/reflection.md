# Reflection

Honestly, this first laboratory activity was pretty challenging for me, especially the part involving the terminal and navigating Linux. Since I was completely new to the command line, even something as simple as creating a new user and switching accounts using `su` took me a few tries before I actually understood what was happening.

The part that confused me the most was using the nano editor. I made several mistakes because I kept getting mixed up about whether I was actually inside nano or still in the regular bash terminal — which caused a bunch of errors whenever I tried pasting text in the wrong place. It was honestly a bit stressful at first, but after enough trial and error, I finally figured out how to use it properly.

Commands like `lscpu`, `free -h`, and `df -h` were all new to me, but they helped me understand how a cloud engineer actually checks the details of a system — from the kernel version down to memory and disk space. Even though it felt technical at first, I actually ended up enjoying this part because it felt like something a real engineer would genuinely use on the job.

Organizing my files and building a proper folder structure for my GitHub repository also taught me how important good documentation really is — it's not just about finishing the task, but doing it in an organized way. I still struggle a bit with Markdown formatting sometimes, but I'm slowly getting more comfortable with it.

Overall, even though I felt lost and confused during some of the early steps, I learned that patience and repetition are really what it takes to get comfortable with Linux and the Git/GitHub workflow. I'm looking forward to the upcoming labs on Docker and Kubernetes, even though I'm a little nervous since I know the topics are going to get more advanced from here.
